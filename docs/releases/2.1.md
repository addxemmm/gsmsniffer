# 2.1 — Single complete image / 单一完整镜像

## Changes / 变更

- One Docker Hub tag: **`addxemmm/gsmsniffer:2.1`**. The image includes gr-gsm/tshark; demo and shielded modes do not require separate images.
- Frontend and same-origin API: `18083`; API-only backend: `8083`. Compose binds both host ports to loopback by default.
- Default mode remains `demo`, with no USB mapping, no automatic jobs and `restart: "no"` (no boot startup).
- The optional shielded Compose override changes runtime mode, permissions and state isolation, not the image tag.
- Source revision labels, image digest and provenance replace extra commit-qualified tags. The [2.0.0 record](2.0.0.md) remains historical.

镜像统一为2.1，依赖完整但不自动启用硬件。前端18083、后端8083，服务不开机自启，Token与数据卷升级时保留。

## Scope / 使用限制

**仅限自有测试SIM、自有终端，在有效屏蔽室或屏蔽箱内使用。**
**Use only owned test SIMs and terminals inside an effectively RF-shielded room or enclosure.**

Identities remain permanently masked and SMS output remains event-only without plaintext bodies. Installed dependencies and HTTP health checks do not prove physical shielding, SDR compatibility or successful RF reception. Physical RF acceptance is a separate laboratory procedure and is not claimed by this release description.

## Optional-authentication update / 可选鉴权更新

Current 2.1 source adds anonymous access when no token file is configured and the environment token is unset/empty. The UI discovers the mode from public `/api/v1/auth` and connects automatically without a token in anonymous mode. Valid configured credentials require login; malformed configured credentials fail startup. The optional `compose.auth.yml` overlay retains file-based login. Anonymous mode grants every reachable client management and data access; restrict it to trusted LAN clients. The earlier acceptance evidence above records its original authenticated deployment and is not evidence for these later changes.
